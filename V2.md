| `/` | `+page.svelte` | Search: desktop table + mobile cards, filter chips, pagination, PDF/CSV export |

## Component Architecture

### `+layout.svelte` (shared shell)

Renders on every page. Contains:

- **Header** (`position: sticky; top: 0`):
  - Brand text: "TGPC" (green) "Rx" (red) "Registry" (gray) — three `<span>` with color classes
  - **Connection status indicator** — small pill with dot animation:
    - States: `connecting` (red dot + "Busy"), `connected` (green dot + "Live" + date + clock), `error` (red dot + "Offline")
    - Dot pulses via CSS `@keyframes pulseScale`
    - Clock updates every second
  - **Stats bar** (7 stat cards in a row):
    - Total Rx, BPharm, DPharm, MPharm, PharmD, QC, QP
    - Each shows a colored-gradient header label and a bold number
    - Desktop: row layout with right borders between cards
    - Tablet (≤768px): 4-column grid, centered
    - Small phone (≤480px): 2-column grid, hides QC and QP
  - **Stats-updated row** below stats:
    - Sync badge (green checkmark + "Synced")
    - Last sync timestamp (purple-blue gradient text, fetched from Supabase `metadata` table)
    - Separator | NOTICES link (purple) | DISPATCH link (red, animated border pulse, PDF icon) | separator | "Unofficial data | Not for legal use"
  - On tablet/mobile: header stacks vertically, brand and stats in full-width rows

- **Footer** (`position: fixed; bottom: 0`):
  - Disclaimer text in 0.55rem gray
  - Content: ⚠️ DISCLAIMER + "unofficial tool" text + 🚫 no liability + ⚖️ Fair Dealing Section 52 + copyright year
  - Padding accounts for safe-area-inset-bottom on mobile

### `+page.svelte` (search page)

**Search section:**
- Title "Search Rx" (gray "Search" + red "Rx")
- Search bar: text input (placeholder: "Enter Name or Registration Number (min 3 chars)") + Search button (green) + Reset button (gray) + Export PDF button + Export CSV button
- On mobile: buttons wrap below input, input gets `font-size: 16px` (prevents iOS zoom)
- Filter chips row: All (active by default) | BPharm | DPharm | MPharm | PharmD | QC | QP
  - Horizontal scroll on mobile (`overflow-x: auto`, hidden scrollbar)
  - Active chip: green background + white text
  - Inactive: gray border, gray text

**Results section** (`max-height: calc(100vh - 275px)`):
- Results header: "Showing X results" count
- Table container (scrollable): both table + mobile cards rendered, CSS toggles visibility
  - **Desktop** (`@media >768px`): `<table>` with columns: Registration Number (blue bold) | Name | Father's Name | Category (color badge)
  - **Mobile** (`@media ≤768px`): cards with reg number + badge top row, name below, father name with "S/O " prefix
- **Pagination bar** (below table, only shown when results > 50):
  - Left: "X-Y of Z" text
  - Right: Previous button | "Page X of Y" | Next button
  - Page size: 50 (desktop), 25 (mobile)
  - Buttons disabled at first/last page
  - Pagination resets to page 1 on new search or filter change

### `notice/+page.svelte` (notices page)

- Header "Notices & Circulars - TGPC" with "Back to main page" link
- Search input with magnifying glass icon
- Year tabs (auto-generated from data, most recent first)
- Table: Date | Title / Description | Links
  - Desktop: standard table with sticky header
  - Mobile (≤900px): card layout where each `<tr>` becomes a block with `data-label` pseudo-elements
- Links render as colored badges: PDF (red), Image (purple), External (blue)
- Data sourced from `static/notice.json` via `fetch('/api/notice')`

### `dispatch/+page.svelte` (dispatch page)

- Header "Dispatch Lists - TGPC" with total file count and "Back to main page" link
- Search input with magnifying glass icon + result badge
- Year tabs with per-year file counts
- File grid: responsive 5-column (desktop) → 4 → 3 → 2 → 1 (mobile)
  - Each file card: PDF icon + formatted date + file size
  - Cards link directly to R2 public URL
- Sorting: most recent first
- Parsing filename format: `DL{DD}{MM}{YYYY}[suffix].pdf` → e.g., `DL27042026.pdf`, `DL03062020C.pdf`
- Fallback: if API fails, renders sample data (list of ~27 hardcoded filenames)

### `+server.ts` files (API routes)

**`/api/notice`:**
- Imports `static/notice.json`
- Returns it as JSON response with CORS headers
- No dynamic processing needed

**`/api/dispatch`:**
- In production: reads from Cloudflare R2 `DISPATCH` bucket binding with prefix `dispatch/`
- In dev (`npm run dev`): returns sample/fallback data
- Returns `[{name: string, size: number}]` sorted alphabetically
- The Cloudflare binding `DISPATCH` must be configured in both `wrangler.toml` and Cloudflare Pages dashboard

## Data Flow Details

### Supabase Client (`lib/supabase.ts`)

```typescript
// Same approach as v1: anon key with RLS
// Reads from SvelteKit public env vars:
//   PUBLIC_SUPABASE_URL
//   PUBLIC_SUPABASE_PUBLISHABLE_KEY
// Initialized once and reused across all pages
```

### Search Query

```sql
SELECT registration_number, name, father_name, category
FROM rx
WHERE registration_number ILIKE '%<query>%'
   OR name ILIKE '%<query>%'
   OR father_name ILIKE '%<query>%'
LIMIT 100000
```

- Minimum query length: 3 characters (2 on mobile)
- Results fetched client-side, then sorted and paginated in memory
- No server-side pagination — all matching results fetched in one call

### Sort Order

Custom prefix priority:
1. `TS` — Telangana State (older format)
2. `TG` — Telangana (newer format, post-abbreviation change)
3. `TSDR` — Telangana State (Doctor of Pharmacy? variant)
4. `TGDR` — Telangana (Doctor of Pharmacy? variant)
5. All other prefixes alphabetically

Within same prefix, sort by numeric portion of registration number ascending.

### Stats Loading

1. On page load: immediately display cached stats from `localStorage` (key: `tgpc_analytics`)
2. If no cache: display hardcoded fallback stats (last known values):
   ```
   total: 85323
   BPharm: 57955, DPharm: 16141, MPharm: 2354, PharmD: 6393, QC: 29, QP: 231
   ```
3. Fire Supabase RPC `get_rx_stats()` — this is a PostgreSQL function that returns:
   ```json
   { "total": 87210, "categories": { "BPharm": 58000, ... } }
   ```
4. If cache total matches live total, skip update (no change)
5. If different, update display and save to localStorage

### Connection Status

1. On DOMContentLoaded: status pill shows red dot + "Busy"
2. Try `SELECT id FROM rx LIMIT 1` against Supabase
3. On success: green dot + "Live" + date (e.g., "04 JUN 2026") + live clock (HH:MM:SS updating every second)
4. On failure: red dot + "Offline"

### Realtime Polling

1. On load: fetch `last_sync` value from Supabase `metadata` table (key: `last_sync`, value: ISO 8601 timestamp)
2. Store in `lastKnownSync` variable
3. Every 5 minutes (`POLL_INTERVAL = 5 * 60 * 1000`):
   - Re-fetch `last_sync` from metadata table
   - If changed: show toast notification "🔄 Database updated! Results refreshed." (auto-hides after 3s), auto-refresh any active search, refresh stats
   - If unchanged: do nothing

### Export

**PDF** (jsPDF + jspdf-autotable):
- Uses `window.jspdf` (loaded from CDN in `app.html`)
- Title: "TGPC Rx Registry - Search Keyword: {query} - {date}"
- Table: all 4 columns, green header row, striped body
- Page numbers at bottom center
- Footer disclaimer on each page
- File: `TGPC-RX-SEARCH-{keyword}-{DDMMYYYY}.pdf`

**CSV** (Blob download):
- First row: metadata comment (`# TGPC Rx Registry - Search...`)
- Second row: column headers
- All data rows with proper quoting (double-quote escaping)
- UTF-8 BOM for Excel compatibility
- File: `TGPC-RX-SEARCH-{keyword}-{DDMMYYYY}.csv`

Both exports use ALL filtered results (`currentResults`), not just the current page.

## Build & Deploy

```bash
cd v2
npm install           # Install dependencies
npm run dev           # Local preview at localhost:5173
npm run build         # Production build → .svelte-kit/cloudflare
npm run preview       # Preview production build locally
```

### Cloudflare Pages deployment
- Connect the `v2/` directory as a Pages project (or use the repo root with build config pointing to `v2/`)
- Build command: `npm run build`
- Build output directory: `.svelte-kit/cloudflare`
- Environment variables: set `PUBLIC_SUPABASE_URL` and `PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- R2 bucket binding: `DISPATCH` bound to the R2 bucket containing dispatch PDFs

### Coexistence Strategy

| Stage | v1 (docs/) | v2 (v2/) |
|---|---|---|
| Development | Unchanged | `npm run dev` on localhost |
| Preview | Unchanged | Cloudflare Pages branch deployment → preview URL |
| Go-live | Still serving | Deploy to production URL |
| Post-switch | Kept as fallback | Serves via updated Worker routing |

At go-live, `_worker.js` is updated to route production traffic to the v2 build output instead of `docs/`.

## Key Differences from v1

| Aspect | v1 | v2 |
|---|---|---|
| Framework | None (vanilla JS) | SvelteKit 5 |
| CSS | Hand-written in `<style>` blocks | Tailwind CSS utility classes |
| Mobile detection | Worker serves separate HTML file | Responsive in one component |
| Page routing | `_worker.js` URL rewriting | SvelteKit file-based routing |
| Shared layout | Duplicated across 4 HTML files | Single `+layout.svelte` |
| Type safety | None | TypeScript interfaces |
| Search JS | ~788 lines monolithic | Component-based with imports |
| Build step | None | Vite + SvelteKit build |
| Env vars | Hardcoded `config.js` | SvelteKit `PUBLIC_` env vars |
